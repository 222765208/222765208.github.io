# Shezz-App — Agile Team Charter
**Updated:** 27 October 2026 · **Project:** Shezz-App

## 1. Team Purpose & Vision
**Mission:** Develop a salon platform enabling customers to book beauty appointments, submit hairstyle references and price offers, and access loyalty rewards.

**Success:** A responsive usable application with working customer flows, verified testing, successful deployment and project documentation.

**Product/service:** User interface, frontend features, application logic and integrations, testing evidence and a deployed demonstration.

## 3. Ways of Working
**Framework:** Scrum-inspired short sprints tracked in Trello.

| Ceremony | Frequency | Purpose |
|---|---|---|
| Daily stand-up | Working days via WhatsApp | Progress, next steps and blockers |
| Sprint planning | Start of sprint | Agree goal, priorities, ownership and estimates |
| Review / demo | End of sprint | Demonstrate features and gather feedback |
| Retrospective | End of sprint | Discuss successes, challenges and improvements |

## 4. Working Agreements
Attend meetings prepared and on time; respect timeboxes; update Trello; raise blockers early; give constructive feedback; review changes before merging; test before marking work complete; share evidence.

## 5. Communication
**Channels:** WhatsApp for coordination, Trello for task tracking, GitHub for code and project history.

**Response expectations:** Acknowledge urgent blockers as soon as reasonably possible; respond to routine messages within one working day subject to study and personal commitments.

**Remote norms:** Remote by default; communicate availability and arrange calls/demos when necessary.

## 6. Decision-Making
Aim for consensus; if unresolved, use a majority vote among the three members. Consider technical feasibility and UI/UX implications. Escalate unresolved matters through Trello discussion and then to the lecturer/supervisor.

## 7. Definition of Done
Feature meets acceptance criteria and UI/UX requirements; code integrated, reviewed and tested; major defects resolved; responsive behaviour verified; documentation, Trello and evidence updated; team demonstration and acceptance; deployment when applicable.

## 8. Core Values
Respect, transparency, accountability, trust and a learning mindset.

## 9. Risks & Constraints
**Risks:** Tight deadlines, unequal workload, integration bugs, deployment issues, connectivity and delayed feedback.

**Dependencies:** Designs, frontend/backend interfaces, repository and hosting access.

**Constraints:** Limited student time, devices, internet, free-tier service limits and technical experience.

**Mitigation:** Clear ownership, small increments, frequent reviews, backups and early deployment testing.

## 10. Review & Improvement
Review at each sprint retrospective or when responsibilities or delivery plans change. **Last updated:** 27 October 2026.
